# Architecture Views and ADR Reference

Choose a view by question: context for actors/systems, container for deployables, component for internals, sequence for behavior over time, deployment for topology, ER for data. Keep each view focused and link it to requirements, threats, tests and owners.

An ADR records one decision, not an entire design. Its minimum contract is: status, date, context, drivers, decision, alternatives, consequences, risks, validation and related IDs. Supersede rather than silently rewrite accepted decisions.

For PlantUML, keep source beside the document, use stable aliases, explicit boundaries and render before publishing. Split diagrams when labels become unreadable or relationships cross excessively.
