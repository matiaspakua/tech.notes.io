# Telemetry and SLO Reference

Define indicators from user and system outcomes: availability, latency, correctness, throughput, saturation and dependency health. An SLO needs a target, window, owner, error-budget interpretation and measurement source.

Structured telemetry should include timestamp, service/version, environment, correlation ID, operation, outcome and duration, while excluding secrets, tokens and unnecessary personal or financial data. An alert is actionable only when it has severity, owner, threshold, deduplication, escalation and a runbook.
