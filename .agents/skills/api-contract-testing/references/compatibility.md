# API Compatibility Reference

Classify changes as additive, behavior-changing or breaking. Check required fields, enum expansion, status/error semantics, pagination, idempotency, timeouts, retries, authentication and authorization. Compatibility must be evaluated from both provider and consumer perspectives.

Contract examples should be synthetic and minimized. Record contract version, provider/consumer, test environment, request vector, expected schema/status, actual result, evidence and remediation owner. Deprecations need notice, migration path and removal date.
